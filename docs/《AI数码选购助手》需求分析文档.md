# 《AI数码选购助手》需求分析文档

**文档目的：**明确《AI数码选购助手》的需求背景、MVP 最小可行范围、后续扩展路径、核心使用流程与分阶段功能核对清单，作为进入开发的基线。

- **产品定位：**面向学生与家长的 AI 电脑选购智能体，电脑品类为主、预留全数码扩展。

# 需求背景

## 市场与用户痛点（来自调研报告）

中国 PC 市场年出货量达 4210 万台（含平板，2025 年，同比增长 6%），高等教育在学总规模 4872\.57 万人，每年高考报名 1335 万人，学生购机是年度高频、刚性的消费决策。但该决策的信息成本持续走高：处理器与显卡代际频繁、型号后缀差异大、国补与学生优惠叠加规则复杂，仅凭电商参数表难以判断。

现有替代方案各有明确边界：平台 AI 导购立场绑定平台、只推站内商品；厂商装机工具只推荐自家品牌；内容社区更新慢、无法一对一响应；通用大模型则存在幻觉、价格过时与兼容性错误，公开实测中其配置单出现电源功率不足、内存不在主板 QVL 列表导致整机无法点亮的问题。这构成本产品的切入空间：用联网检索保证时效、用智能体工具编排保证分析深度、用 HITL 多轮确认把拍板权留给用户。

# MVP 最小可行功能点

MVP 要构成一个可演示的最小闭环：用户打开网页即可对话、能拿到配置单、能多轮调整，全程免登录、无需数据库。各功能点以需求卡形式列明触发、系统行为与验收要点。

|编号|功能点|触发与用户意图|系统行为|验收要点|
|---|---|---|---|---|
|M1|**免登录网页访问**|用户打开网页，手机或电脑浏览器进入|无需登录，页面直接可用并自适应不同屏幕|打开即可对话；手机与电脑端布局均可用、无横向滚动|
|M2|**多轮对话需求采集**|用户描述预算、用途、品牌偏好|通过追问补全关键信息，结构化记录需求|预算、用途、偏好三类信息缺失时系统会主动追问|
|M3|**简单需求快速响应**|用户提出明确、简单的咨询|大模型直接多轮对话回答，不调用智能体|响应及时，回答与用户问题直接相关|
|M4|**复杂需求智能体处理**|用户需求复杂、需要详细配置与分析|ReAct 智能体编排：先 Tavily 搜索，信息不足再 Firecrawl 爬取，经 Function Calling 与 MCP 调用工具|工具调用顺序可观测；搜索不足时才触发爬取；过程可追溯|
|M5|**配置单与分析输出**|智能体完成信息收集与分析|生成结构化配置单，附选型理由与预算分析|配置单含具体型号、价格、用途说明与预算汇总|
|M6|**HITL 多轮确认**|用户查看配置单后要求修改或确认|支持针对单项调整并重新生成，用户确认后定稿|调整后配置单同步更新；用户确认后输出最终版本|
