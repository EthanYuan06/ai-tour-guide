# 百炼知识库调参计划（单库 · 基线跑通→优化 · 最少调试次数）

> 配套《AI 智能导游 - RAG 开发文档》阶段一「离线调参」。总体方案见 [ai-guide-rag-design.md](./ai-guide-rag-design.md)。
> 本文档放 `docs/` 根目录，**不放 `docs/rag/`**（后者专供向量库入库，混入会被 ETL 误切分）。
> 全程百炼官网 UI 手动操作，**不上 CLI / 脚本**；本文件即唯一交付物。
> **只用一个「自定义正则切分」知识库**（不建智能切分对照库）：最终目标是把调好的参数直接落地本地 Spring AI + pgvector，智能切分对照库只为制造 A/B 差值、属额外工作量，已弃用。

---

## 一、目标与约束

- **业务目标**：行程规划形态输出，但数字 / 体验 / 注意事项 / 签证政策必须忠于私域语料（抗幻觉）。
- **当前任务**：在**一个按条目切分的知识库**上把检索/生成参数调好，**直接用于编程开发**。
- **指标诉求**：一个有权威性、应届生友好、时间成本低的量化指标，形态为「**基线参数先最低跑通业务流程 → 后期加某项优化提升回答质量**」的前后对比。
- **最少调试次数**：固定小题集 × ≤3 组配置，单变量递进，不做大网格。

**语料现状（脚本核实）**：`docs/rag/` 8 篇、78 条目、约 1 万字、平均 125 字/条、最长 728 字（签证主条）。

## 二、前置硬门槛：把切分修到「每条目一片」（先做，否则不测）

### 2.1 当前切片的问题（截图诊断，旅游体验-关东 11 条目）

| 现象 | 截图证据 | 危害 |
|---|---|---|
| **不是每条目一片** | 11 条目只切出 **6 片**；片2=新宿站+歌舞伎町(192字)、片3=大久保公园+秋叶原(233字) | 仍一片多条目→向量稀释、召回带无关内容，「按条目切分」前提不成立 |
| **孤儿「【」** | 每片开头多一个单独的「【」行，真正的元数据头在其后 | 分隔符把括号拆脱，元数据头不在片首→来源标注/标签过滤受损 |
| 切分未达预期 | 正则疑似写成 `?=【`（缺括号） | `?=【` 不是合法零宽断言，未在每个头前切 |

**结论：当前切片不能直接用于测试。** 必须先修到每条目一片，否则后续调参归因与本地 TextSplitter 映射都建立在错误切分上。

### 2.2 修复配置

- 切分方式：**自定义切分 → 正则**。
- 分隔符：**`(?=【)`**（零宽正向前瞻，**必须带圆括号**；在每个元数据头 `【` 前切、且不消耗括号，保证每片以完整 `【…】` 头开头）。
- 分段长度：**800**（≥ 最长条目 728，保证签证长主条不被腰斩）；重叠：**0**（条目自包含）。
- 排序模型模式：问答模式（创建后不可改，保持默认）。
- 导入同样 8 篇。
- 备选：若正则仍异常，改用**空行分隔** `\n\s*\n`（语料每条之间恰一空行、条内无空行，天然每条目一段）。

### 2.3 验收（以切片数为准，逐文件核对，全过才进入调参）

| 文件 | 期望切片数 |
|---|---|
| 消费明细-交通 | 17 |
| 旅游体验-关西 | 12 |
| 旅游体验-关东 | **11**（当前 6，须修到 11） |
| 消费明细-餐饮购物娱乐 | 10 |
| 消费明细-住宿与城际 | 9 |
| 注意事项-礼仪与交通 | 8 |
| 消费明细-证件与换汇 | 6 |
| 签证要求-短期观光 | 5（728 字主条须整块在一篇内） |

抽查任一切片，区分**标题**与**正文**：

- **正文**必须含完整 `【类别｜…】` 元数据头 + 该条目的客观/主观（或规则/后果）正文，且**一片只含一个条目**——这才是 embedding 与 grounding 实际使用的内容。
- **标题**若显示为单个「【」（UI 自动取首行/首字符所致），属 **cosmetic 展示问题，可接受**，不影响检索与来源核对；只要正文头完整即可，**不必为标题再折腾切分**。
- **计数验收**：切片数 = 条目数（关东 11、全库 78）。「无杂糅」只排除了一片多条目，还须排除**一条目被腰斩成两片**（过度切分）；以计数为准。

若仍一片多条目，说明 Bailian 按分段长度合并相邻段——调整分段长度或改空行分隔 `\n\s*\n`，反复确认到计数吻合，不靠猜。

## 三、唯一核心指标：回答达标率（基线 → 优化）

### 3.1 定义

固定 **6 道计分题**，每组配置跑一遍，按 §3.2 标准逐题判「达标 / 不达标」：

> **回答达标率 = 达标题数 ÷ 6**

- **基线 X%** = 最低跑通配置（C0）的达标率。
- **优化 Y%** = 递进加优化项后（C1/C2）的最优达标率。
- **简历核心数字 = X% → Y%**，差值归因于「加的那项优化」（单变量）。

### 3.2 判定回答质量的符合标准（rubric，逐题打 ✓/✗）

一题记 **达标** 当且仅当 R1–R4 **全 ✓**：

| 编号 | 标准 | 判 ✓ 的条件 | 典型 ✗ |
|---|---|---|---|
| R1 | **事实准确** | 该题 gold 事实全部正确（数字/规则/体验），无编造、无数字错配 | 把 27512 円记错、净省算错、编造未述体验 |
| R2 | **口径正确** | 住宿=个人分摊非整间价；不编造单一全程总额；换日元2500=换汇非消费；签证用官方/一手口径 | 答「整间148」、虚构全程总花费、把换汇当消费 |
| R3 | **有据可溯** | 开「引用」，所答事实能在召回切片中找到对应语料条目 | 答案事实不在任何召回切片里（凭空生成） |
| R4 | **库外不硬编** | 语料没有的内容（如工作签）标明无依据/拒答 | 用模型记忆编造工作签流程 |

- 任一 ✗ 记不达标，并在记录表标失败项（R1/R2/R3/R4）便于归因。
- **只评事实与 grounding**；行程编排/天数/备选等规划创意不计入达标（那是提示词形态，非检索质量），避免混淆归因。
- 定性观察（不计分）：库外工作签是否拒答、整间148陷阱是否纠正——用于佐证 R2/R4。

### 3.3 为什么不用 Recall@5（一句话）

全库仅约 1 万字、粗切分约 7 片，top-5 覆盖约 71% 全库，Recall@5 会奖励粗切分、无法体现优化收益；达标率是端到端「回答是否可信」，直接对应抗幻觉目标，且纯 UI 读答案+引用即可判。

### 3.4 简历表述模板（填实测数字）

> 「在**按条目自定义切分**的私域旅游知识库上，以最低配置跑通问答基线，再通过 **[启用 rerank / 阈值与 top-k 调优]** 单变量递进优化，使**回答达标率从 X% 提升至 Y%**（6 题固定测试集、R1–R4 人工 rubric 评分），并将切分/阈值/top-k 参数直接落地 **Spring AI + pgvector**。」

## 四、最小调试阶梯（≤3 组配置，单变量）

| 配置 | 检索模式 | Query改写 | 排序模型(rerank) | 相似度阈值 | 最大召回(top-k) | 目的 |
|---|---|---|---|---|---|---|
| **C0 基线跑通** | 极速 | 关 | 关/默认* | 0.20 | 5 | 最低成本跑通业务流程，得 X% |
| **C1 +优化A** | 极速 | 关 | **开(qwen3-rerank)** | 0.20 | 5 | 单变量加 rerank，看精排收益 |
| **C2 +优化B** | 极速 | 关 | 开 | **0.30** | **8** | 在 C1 上收紧阈值+放宽召回，看 grounding 收益 |

\* 若排序模型创建后不可关（基线已含 rerank），则 C1 改为「+top-k 8」、C2 改为「+阈值 0.30」，仍保持每步单变量；rerank 收益改在本地阶段三验证。
- 每组跑同一 6 题，记达标率；**保留达标率最高且回答不过载的配置**作为最终参数。
- 若 C1/C2 不优于 C0，如实记录（优化无增益），最终参数取 C0。
- 可选加跑（时间充裕才做）：Query改写开（多轮/模糊问题），不计入核心前后对比。
- **调试次数上限**：6 题 × 3 配置 = 18 次提问 + 定性 2 题 × 3 = 6 次，共约 24 次 UI 提问。

## 五、固定题集 + gold + 护栏（6 计分 + 2 定性）

> gold 核对点 = 回答必须正确陈述的事实；护栏 = 不得出现的错误；定位 = `docs/rag/` 真实条目（6 题定位合计 14 处、13 唯一条目，已脚本核对存在）。

### Q1 去日本旅游消费如何？
- gold：① 住宿个人分摊合计 ¥1981.35（大阪490/京都148/东京990.85/上海352.50）；② 城际大交通合计 ¥2585（880+1234+471）；③ 当地交通全程 27512 円≈1343 元。
- 护栏：不编造单一全程总额；住宿个人分摊；换日元2500=换汇非消费。
- 定位：住宿与城际·住宿汇总 / 城际交通汇总；交通·全行程汇总。

### Q2 交通费贵不贵？
- gold：① 全程 27512 円≈1343 元；② 米原→东京新干线 12100 円占约44%；③ 东京三日券1500円抵消3082、净省1582。
- 护栏：占比/净省不算错；三日券仅覆盖 Metro+都营。
- 定位：交通·全行程汇总 / 城际·新干线 / 东京三日券。

### Q3 有什么需要注意的？
- gold：① 女性车厢分时段；② 不乱动外送点餐机；③ 去成田坐京成特急（快速不到）；④ eVISA 须联网手机现场出示、截图/PDF/打印不接受。
- 护栏：不编造未述注意项；eVISA 官方口径。
- 定位：注意事项·女性车厢 / 外送点餐机 / 京成特急vs快速；签证·eVISA机场出示规则。

### Q4 大学生去日本签证怎么办、多少钱？
- gold：① 大学生免资产通道（教育部直属在校/研究生/毕业3年内，在学证明或毕业证替代经济证明，仅限本人）；② 2026-07 起官方单次715元、代办均价约830元、2025学生通道约270元。
- 护栏：签证费官方/一手口径；「10万存款官方门槛」为网传误区不得采信。
- 定位：签证·大学生免资产证明通道 / 2026-07签证费上调。

### Q5 京都酒店多少钱一晚？
- gold：京都酒店**个人分摊房费 ¥148**（多人合住均摊、非整间房价、合住人数未注明）。
- 护栏：**不得答整间148**；不臆造合住人数/日均。
- 定位：住宿与城际·京都·住宿。

### Q6 伏见稻荷大社值得去吗、怎么安排？
- gold：① 九点前人少适合拍照；② 要爬山、体力好再来（三人爬一小时一半没爬到）；③ 山顶没什么看、底下神社还好。
- 护栏：不编造未述景观；不把未登顶说成登顶。
- 定位：旅游体验-关西·伏见稻荷大社。

### 定性A（不计分）日本工作签证怎么办？→ 观察是否拒答/标无依据（R4）。
### 定性B（不计分）京都酒店是不是整间只要148？→ 观察是否纠正个人分摊口径（R2）。

## 七、最终本地参数映射（Spring AI + pgvector）

| 百炼结论 | 本地落点 |
|---|---|
| 按条目切分 `(?=【)` / 长度800 / 重叠0 | 自研 `TextSplitter`/`DocumentTransformer`（ETL 按元数据头切条目） |
| 最优相似度阈值 | 检索 `similarityThreshold`（`application.yml` 单源） |
| 最优 top-k | 检索 `topK`（`application.yml` 单源） |
| rerank(qwen3-rerank)/问答模式 | 阶段三自研 `DocumentPostProcessor`（对接 DashScope rerank） |
| 极速模式 | 阶段二 `QuestionAnswerAdvisor` / 阶段三 `RetrievalAugmentationAdvisor` 基线 |
| embedding 模型 | 与百炼一致（入库前核实型号，本地 `EmbeddingModel` 对齐） |

> 百炼仅离线调参参考；生产索引/ETL 落本地 Spring AI + pgvector，二者不混用。

## 十一、企业常见开发规范

- **单变量对照**：每步只改一个参数，归因清晰。
- **数据单源**：gold 唯一来源 docs/rag；指标口径（达标率=达标/6、R1–R4）全文一致。
- **可复现**：固定题集+固定 rubric+记录表，他人可重跑同指标。
- **最小可行**：单库、≤3 配置、纯 UI、单文件交付，不引入脚本/CLI/xlsx/对照库。
- **分层与单一职责**：只新增本计划文档，不触碰语料/代码/配置/设计文档。
- **来源可追溯**：开引用，回答标注召回切片，便于验证排错。
