# 《AI数码选购助手》方案设计文档

**核心结论：**MVP 采用免登录、无数据库的纯 AI 架构，聚焦“对话采集 → 智能体联网分析 → 配置单输出 → 多轮确认”闭环。

- **技术栈：**前端 Vue 3，后端 Spring Boot 3 \+ Spring AI Alibaba，大模型 DeepSeek，联网工具 Tavily \+ Firecrawl。

- **交付与部署：**Docker Compose 编排，Nginx 托管前端并反向代理，适配 2 核 2G 云服务器。

- **关键取舍：**登录、用户体系、支付全部后置，后端无状态、以会话 ID 串联对话，后续可平滑补回登录能力。

# 方案概述与设计前提

## 设计目标与范围

本方案基于已交付的市场调研报告与需求分析文档，目标是给出一套可直接进入编码的技术实现路径。本期只实现 AI 选购核心能力，验证智能体联网分析与配置单输出的完整链路，作为求职作品集的核心项目；不追求独立商业上线，不承担用户账户、数据持久化与交易职责。

范围内包括：多轮对话界面、需求采集与结构化、简单/复杂需求分流、ReAct 智能体编排、联网搜索与爬取、工具调用、配置单生成与多轮确认。范围外包括：登录注册、数据库与用户体系、VIP 支付、机箱定制交易、小程序与多端分发，这些在需求文档中已标注为扩展功能。

## 免登录前提与设计影响

登录功能依赖用户表、鉴权接口与会话持久化，会显著拉长 MVP 周期，且与验证 AI 能力的目标无关。去除登录后，系统设计相应做出四点调整，这也是本方案与初版需求的核心差异。

|设计维度|免登录方案|后续补登录的路径|
|---|---|---|
|**身份识别**|前端首次进入生成随机会话 ID，随每次请求携带，无需用户感知|登录后以用户 ID 关联会话 ID，历史对话可归属到账户|
|**后端状态**|应用保持无状态，短期上下文存内存，重启即清空|引入数据库或 Redis 持久化对话记录，接口无需重构|
|**对话历史**|当前会话历史由前端本地保存并回传，刷新页面可恢复当次|云端留存后支持跨设备查看与多方案管理|
|**访问控制**|页面开放直连，Nginx 仅做路由与限流，不做鉴权|在网关层增加 Token 校验，AI 接口保持不变|

# 技术选型与对比

## 选型总览

整体选型遵循三条原则：优先复用本人已掌握的 Java 与 Vue 技术栈以保证交付；优先选择对国内模型与网络环境友好的生态；在 2 核 2G 资源约束下保持组件轻量。最终选型与理由如下。

|层次|选定技术|核心理由|
|---|---|---|
|**前端**|Vue 3 \+ Vite|沿用现有技能，响应式渲染适合流式对话，构建产物轻量|
|**后端框架**|Spring Boot 3 \+ Spring AI Alibaba|Graph 编排与预置节点适配智能体，国内模型友好|
|**大模型**|DeepSeek（deepseek\-chat）|Tool Calls 成熟、成本极低、中文与代码能力强|
|**通信方式**|SSE 流式（HTTP）|单向推送场景实现简单，自动重连，无需 WebSocket 复杂度|
|**部署**|Docker Compose \+ Nginx|容器隔离、一键编排，适配低配服务器与本地一致环境|

## 前端选型：Vue 3 对比 React 与原生方案

|对比维度|Vue 3（选定）|React|原生三件套|
|---|---|---|---|
|**学习与复用**|本人已掌握，零切换成本|需另学 Hooks 生态，成本高|入门简单但无工程化|
|**流式渲染**|响应式数据驱动，增量更新自然|同样支持，写法略繁琐|手动操作 DOM，易出错|
|**组件化维护**|单文件组件，结构清晰|组件化成熟，生态最大|复杂界面维护性差|
|**构建与体积**|Vite 构建快，产物可静态托管|产物相近，配置较重|无构建，最轻量|

结论：Vue 3 在技能延续、流式渲染与工程化之间最平衡；React 生态虽大但对本项目无额外收益，原生方案难以支撑多轮对话与配置单的复杂交互。

## 后端 AI 框架选型：Spring AI Alibaba 对比 Spring AI 与 LangChain4j

|对比维度|Spring AI Alibaba（选定）|Spring AI|LangChain4j|
|---|---|---|---|
|**框架定位**|AI Agent 开发框架，基于 Graph 做工作流与多智能体|底层原子能力框架，提供模型适配、工具与向量库抽象|LangChain 的 Java 实现，接口化、颗粒度细|
|**编排能力**|15\+ 预置节点，ReAct/多智能体开箱即用|提供基础抽象，复杂流程需自建|灵活但需自行组装，掌控度高|
|**生态绑定**|绑定 Spring，与 Spring Boot 无缝集成|Spring 原生，零改造|不强依赖 Spring，可独立使用|
|**国内模型友好度**|高，优先适配国内主流模型与本地化场景|取决于适配器，持续增强中|覆盖较全，本地化一般|

结论：本项目核心是 ReAct 智能体与工具编排，Spring AI Alibaba 的 Graph 框架与预置节点直接命中需求，且对国内模型友好；Spring AI 是其底层依赖、能力偏原子，LangChain4j 更适合需要深度定制或脱离 Spring 的场景。

## 流式通信与部署选型

对话结果需要逐字呈现。SSE 基于标准 HTTP 做服务端单向推送，浏览器原生支持、可自动重连，配合后端 SseEmitter 与前端 fetch 的 ReadableStream 即可实现；WebSocket 面向双向实时通信，对本场景属于过度设计。因此选择 SSE，前端用 fetch 读取流并以 TextDecoder 增量解析，规避 EventSource 仅支持 GET 的限制。

部署采用 Docker Compose 编排 Nginx 与后端应用两个容器：Nginx 负责托管 Vue 构建产物、反向代理 SSE 接口并做基础限流，后端容器独立运行 Spring Boot 胖包，外部 API 密钥通过环境变量注入，不写入镜像。

# AI 功能设计

下图以时序图展示一次复杂需求从前端发起到配置单流式返回的完整交互，包含简单/复杂分流与联网工具的调用顺序。

## 会话与上下文管理

前端进入页面时生成一个随机会话 ID 并保存在本地，每次请求在请求头携带。后端以会话 ID 为键在内存中维护短期 ChatMemory，保存最近若干轮消息用于多轮理解；同时前端本地保留完整消息列表，在刷新页面后回传以恢复当次上下文。由于免登录且无数据库，上下文不做长期持久化，设置消息条数与 token 上限，超出后按时间裁剪，避免上下文膨胀推高成本。

## 复杂度分流设计

系统在每轮对话后做一次轻量意图判断：信息明确、无需检索的简单咨询（如概念解释、单一型号对比）直接走大模型对话链路，快速流式回答；需要完整配置、涉及预算分配或多部件权衡的复杂需求，则进入 ReAct 智能体。分流结果对用户透明，仅在内部决定是否调用工具，目的是避免简单问题过度消耗联网额度，同时保证复杂问题的分析深度。

## ReAct 与 Graph 编排

复杂需求交由 Spring AI Alibaba 的 Graph 编排，按“推理—行动—观察”循环推进：模型先基于当前信息推理下一步应调用的工具，执行后将结果作为观察返回，再决定继续检索还是汇总输出。Graph 以节点形式串联模型调用、搜索、爬取、工具分析与结果生成，每个节点的输入输出可记录日志，使思考与执行步骤可追溯，也便于在演示中展示智能体的工作过程。

## 工具函数与 MCP 接入

通过 Function Calling 把可被模型调用的能力注册为工具，模型依据需求自主选择；同时以 MCP Client 接入标准化外部工具，保持工具协议可扩展。核心工具如下。

|工具|触发时机|作用|
|---|---|---|
|**需求结构化工具**|对话中信息补全后|把预算、用途、偏好整理为标准字段供后续节点使用|
|**Tavily 搜索**|进入智能体后首先调用|检索型号、评测与价格信息源，返回结构化摘要|
|**Firecrawl 爬取**|搜索信息不足时补充|抓取指定网页正文，获取详细参数与价格|
|**MCP 外部工具**|需要标准化能力扩展时|以统一协议接入更多工具，不改动主流程|

## 联网工具与顺序控制

联网工具严格按“Tavily 先搜、Firecrawl 补爬”的顺序执行：先以低成本搜索快速获取信息源，仅当模型判断信息不足、需要某页面详情时才触发爬取。该顺序控制写进 Graph 节点条件，既保证信息充分，又把两类工具的调用次数控制在免费额度内。每次外部调用均记录来源链接与时间，配置单中据此标注信息出处，增强可信度。

## Prompt 设计与结构化输出

系统提示词承担角色设定与规则约束，明确智能体是面向学生与家长的电脑选购顾问，要求基于联网结果作答、不臆造价格、对兼容性保持谨慎，并在信息不足时主动追问。输出环节利用 DeepSeek 的 JSON Output 能力，约定配置单结构，确保结果可被前端稳定解析。配置单至少包含部件类别、具体型号、参考价格、选型理由与预算汇总五类字段，简单需求与复杂需求复用同一输出结构。

# 部署与运行方案

## Docker Compose 编排

Compose 定义 Nginx 与后端两个服务：Nginx 容器挂载 Vue 构建产物，将 /api 路径反代到后端，并针对 SSE 关闭缓冲、拉长超时以保证流式不中断；后端容器基于精简 JRE 镜像运行 Spring Boot 胖包，通过环境变量读取 DeepSeek、Tavily、Firecrawl 的密钥。两服务在同一 Compose 网络内通信，对外只暴露 Nginx 端口，后端不直接暴露，降低攻击面。

## 低配服务器 JVM 调优

2 核 2G 环境下需显式约束 JVM 内存，避免容器被 OOM 杀死。开启容器感知并以 MaxRAMPercentage 限制堆占比，为非堆与原生内存预留空间，同时选择低停顿垃圾回收器。关键参数如下，具体取值在部署后结合 Native Memory Tracking 实测校准。

```bash
JAVA_TOOL_OPTIONS=-XX:+UseContainerSupport -XX:MaxRAMPercentage=70.0 -XX:InitialRAMPercentage=50.0 -XX:+ExitOnOutOfMemoryError
```

按 2G 总内存估算，堆上限约 1\.4G，其余留给 Metaspace、直接内存与系统进程；配合分层镜像减小镜像体积、关闭不必要的自动装配，可在该规格下稳定运行。前端为纯静态资源，几乎不占用后端内存。

## 风险与应对

|风险|应对措施|
|---|---|
|**模型幻觉与兼容性错误**|强制基于联网结果作答、标注来源与时间；P1 落地兼容性规则引擎做功率与 QVL 校验|

|**密钥泄露**|密钥仅经环境变量注入、不入库不入镜像，前端不持有任何外部 API 密钥|
